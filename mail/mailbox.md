# 邮箱处理规范

流程的入口常是邮箱里的一封投递邮件。本单元规范投递邮件的进人、识别、去重、记状态与核对，与具体业务无关。

## 进人

仅收件箱进人：待处理对象以收件箱里的未读邮件为准，其余文件夹（如 Spam、自定义归档文件夹）只用于补拉留档与人工核对，不作进人来源。进人若依赖文件夹名，文件夹一改口径就断。

## 识别

未读即未处理：收件箱里的未读投递即待处理对象，处理完即标记已读；未读状态本身就是「还没轮到它」的唯一标记，不再另记一份待办。

发件人即邮箱：来信人邮箱取自发件人，不另存一份。

## 去重

同人重复投递只留一条：同一发件人多封投递，取最早日期的一封，其余随此人一并归档，不重复处理、不重复发信。

## 记状态

文件夹即状态：邮件落在哪个文件夹就是哪个状态，状态不另存一处。处理完的邮件移入流程约定的归档文件夹，即视为状态推进。

一次 modify 双动作：标记已读与移入文件夹是同一条 `modify` 调用的两件事，`remove_label_ids` 摘掉 `UNREAD` 即已读，`add_folder` 即移入，不拆成两次写。

```bash
lark-cli mail user_mailbox.messages modify \
  --message-id "$message_id" --user-mailbox-id "$MAILBOX" \
  --data '{"add_folder": "<folder_id>", "remove_label_ids": ["UNREAD"]}' \
  --as user --format json
```

状态可重建：进人以收件箱为准，状态随时可从飞书侧原始数据（文件夹、已读标记）重建，不依赖本地账本。

## 核对

发后回读不推进：发信后按主题回读发件箱或归档文件夹核对，核对只是核对，不属处理步骤，不作推进条件。

```bash
lark-cli mail +triage --mailbox "$MAILBOX" --filter '{"folder":"SENT"}' --max 10 --format json
```
